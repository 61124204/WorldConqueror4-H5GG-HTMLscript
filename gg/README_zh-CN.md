# 世界征服者4 · GameGuardian Lua 实验移植版

**0.1.0：已完成 Lua 逻辑移植与模拟测试，尚未验证 Android 游戏内存布局。**

来源：`61124204/WorldConqueror4-H5GG-HTMLscript`，基线提交 `08b60e144ea30baca569f73fba82b813695f43c6`，`index.html` blob `97fe98ad0c919d0fabbb3d9ef2d327f6e06c83b9`。只新增 `gg/`，不改原 HTML 和素材。仓库将领、技能 JSON 标注来源为 **3.5.3 明文数据**；这不是 Android 兼容性证明。

## 使用

1. 备份自己的离线游戏存档，在 Android GameGuardian 中选中正确的《世界征服者4》进程。脚本不提供 root、虚拟环境或进程访问权限。
2. 在 GitHub 选择 `feat/gameguardian-lua-port` 分支，下载完整仓库 ZIP 并解压。保留 `gg/` 与 `assets/` 的相对位置，然后在 GG 中执行 `gg/WorldConqueror4_GG.lua`。
3. 确认启动界面中的包名、PID 和游戏版本。先测试“三项资源联合搜索”，输入实际经济、工业、科技数值，唯一匹配后小幅修改，观察是否确实影响目标。
4. 取消主菜单返回游戏；点击 GG 悬浮按钮重新打开菜单。**换局、载入存档、单位消失后，先解除锁定，再重置会话并重新搜索。**

单独下载 Lua 也能进入菜单：缺少资料时，将领、面板、技能槽、技能替换使用手动 ID/属性输入；资源、兵种、勋章、礼包不依赖资料文件。初始国家功能必须有对应 JSON。聊天附件中的源码与测试 ZIP 不含原仓库资料，完整资料请使用 GitHub 分支 ZIP。

推荐目录：

```text
仓库目录/
  gg/WorldConqueror4_GG.lua
  assets/generals/generals-type1.json
  assets/skills/skills.json
  assets/stages/initial-countries.json
```

资料也可放在 Lua 同目录下的 `data/` 中，直接使用上述三个 JSON 文件名。读取优先级为 `data/`、`../assets/`、`assets/`。脚本没有网络请求，不下载或执行远程代码。

## 功能与源规则

| 功能 | 实现规则 |
| --- | --- |
| 经济、工业、科技 | 与 518867 异或，经济基址 +0/+4/+8；支持单值、三值及变化后过滤 |
| 初始国家 | 剧本资料中的三项资源与颜色同时匹配；颜色失败不退回仅资源匹配 |
| 国家设置 | 阵营：经济 -0x84；颜色：+0x94；玩家可控：+0x98 |
| 将领替换与面板 | ID 与当前六维星级联合核验；面板 +0x54 至 +0x68，间隔 4 |
| 技能槽 | ID +0x68 起核验初始/上限各六项；+0xB0、+0xB4 写 5 |
| 技能替换 | 原、新技能分别核验 Lv1/Lv2 连续 ID；改原 ID，并在**目标技能结构** +0x4C 写 1 |
| 原版贸易勋章规则 | 唯一 `100;37500` 连续结构；基址及 +0x20/+0x40/+0x60/+0x80 写 -2000 |
| 进修礼包 | 连续 `300;0;0;当前库存`；多候选经确认后临时标记，观察后还原全部，再写最终库存 |
| 兵种属性 | 当前生命/上限连续核验，可修改生命、移动、士气、技能持续/冷却、攻击状态 |
| 修改管理 | 写入回读、失败恢复、当前会话倒序撤销、受控锁定、诊断导出 |

六维顺序：**行军、步兵、坦克、炮兵、海军、空军**。面板值限 0–6。

单位生命基址字段：当前生命 `+0`、生命上限 `+4`、移动 `+8`、士气持续 `+0x1C`、士气状态 `+0x20`、技能持续 `+0x38`、技能冷却 `+0x3C`、攻击状态 `+0x50`。士气限 -3 至 1；攻击状态按源规则为 **0 可攻击、1 不可攻击**。

勋章功能保留源规则，不是直接输入勋章余额；两个锚点也不能证明其余四个写入位置的对象身份。礼包候选最多允许 64 组临时标记。

**一键通关没有实现。** 原 HTML 只显示“需要单独提供通关标识”，没有搜索或写入逻辑；本版保留说明入口，不猜测地址。网页图标、声音、头像界面没有移植，改用 GG 原生菜单。

## 检查与修正

原资源搜索只取前 512 条，初始国家最多取 2048 条，可能漏掉后面的重复匹配。新版按 256 条完整分页；首轮超过 200,000 条则整次中止，不截断后宣称唯一。读取失败、重复分页、缺失分页都会中止。

原初始国家逻辑在颜色无匹配时退回三资源匹配；新版不采用此退路。原兵种逻辑优先保留“后一项也等于当前生命”的地址，可能漏掉受伤目标；新版要求输入当前生命与生命上限。

原多字段写入可能部分成功；新版保存旧值、重新核验、暂停进程、写入、回读，失败时尝试还原。原 `saveRecords=()=>{}` 没有持久化实现；新版明确将撤销限定为当前脚本会话，并提供诊断文本导出。

GG 的整数运算与标准 Lua 不完全相同：例如整数作为第一个操作数时除法会截断。因此目录页数使用 `(数量 + 每页数量 - 1) / 每页数量` 后向下取整，避免遗漏末页。异或使用明确的 32 位运算过程，不把 Lua 的幂运算 `^` 当作异或。

## 写入、锁定与恢复边界

每批读取前后、每次写入前均检查目标身份。写入确认后再次检查定位条件与旧值；若值已变化则拒绝。只恢复本操作暂停的同一进程，原本被用户暂停的进程保持暂停。

这不是操作系统级原子事务。检查与 API 调用之间仍可能发生竞争；PID 也不能识别同一进程内对象释放、复用或换局，不能绝对排除 PID 复用。**内存回读一致不代表已确定正确游戏对象，更不代表偏移已适配。**

GG 保存列表中已有冻结项与目标重叠时会拒绝写入，不删除用户的保存列表。脚本会清空 GG 搜索结果，正常退出恢复原搜索区域。默认搜索匿名区、C 分配区、C BSS、C 数据区，可在菜单调整。

“保持数值”使用脚本空闲循环，不添加 GG 原生冻结项。对话框打开期间暂停保持；邻近字段变化时停止该项保持；退出或强制停止脚本后不会继续保持。该保护较保守，游戏自然改变其他字段也可能解除保持。

写入失败且即时回滚也失败时，保留待恢复记录并阻止新修改。“恢复未完成写入”只接受仍为原值或拟写入值的字段；出现其他数值就拒绝覆盖。“撤销最近一次修改”必须倒序进行，当前值仍须等于上次写入值；先解除本脚本锁定再撤销。

礼包临时标记期间只能打开界面观察，**不要领取、购买、消耗、保存、换局或强制停止脚本**。正常取消及可捕获异常会尝试恢复，但断电、系统杀进程、GG 强制结束无法保证执行清理。待恢复内容未处理时不要保存游戏；必要时从事先备份的存档恢复。

菜单可导出 `WC4_GG_diagnostics.txt`，包含目标信息、搜索计数、修改地址及旧新值、待恢复记录。不会上传或重新加载旧地址。该日志不是游戏存档备份；目录不可写时会报错。

## Android 适配状态

`C.profile` 集中保留 H5GG 源偏移。本次没有 Android APK、进程内存、设备或模拟器完成游戏实测，**没有已验证的 Android 专用偏移表**。32 位与 64 位的布局可能不同，不能简单把 iOS 偏移乘二。

搜索使用所选区域的 `0..-1` 范围，不照搬 iOS 的 `0x200000000` 上限，并拒绝超过 Lua 安全整数范围的地址。没有唯一结果时应核对目标进程、实际数值、资料版本、已进入的游戏界面和内存区域；不要通过删除核验或强写首个结果来规避失败。

测试使用模拟 `gg` API，不访问 Android。标准 Lua 测试不是完整 GG 运行时模拟，更不是实际游戏兼容性测试。Python 运行器只使用系统 Lua 或 liblua，不下载依赖。
